# Contributing to Galleon Labs

Thanks for helping make the projects easier to use. Bug reports, clearer documentation, accessibility improvements and focused code changes are all welcome.

## Choose the right repository

Use the repository closest to the change. Each project's README explains its setup, and its own contributor guide takes precedence over this shared guide.

- [Boomkin](https://github.com/galleonlabs/boomkin): Hermes onboarding, profiles and skill installation.
- [crypto-defi-skills](https://github.com/galleonlabs/crypto-defi-skills): infrastructure, data, LP and Hyperliquid workflows.
- This repository: the organisation profile and shared community files.

## Report a problem

Describe what you expected, what happened and the smallest steps that reproduce it. Include relevant versions and redacted error output. If issues are disabled in a project, use the contact route in its README.

Keep credentials, wallet keys, personal account data and private logs out of public reports. Follow [SECURITY.md](SECURITY.md) for vulnerabilities.

## Propose a change

For a substantial addition, discuss the user need before implementing it. Small fixes can go straight to a pull request. Keep the change focused, preserve existing user data and run the checks documented by the project.

Explain the result and the checks you ran. Include screenshots for visual changes and current primary sources for protocol or provider claims. State any remaining limitation plainly.

For changes here, run `bash scripts/validate.sh` and inspect the rendered profile when its layout changes. Contributions to these shared files use the [MIT license](LICENSE); other repositories follow their own licenses.

## Credit and reuse

Retain existing authorship and license notices in contributions and derived work. [ATTRIBUTION.md](ATTRIBUTION.md) explains MIT notice requirements and offers an optional visible credit line.
